### 이번 실습에 사용하는 매크로 및 함수

| 이름                                      | 위치                | 하는 일                                                   |
| --------------------------------------- | ----------------- | ------------------------------------------------------ |
| `PTE_V · PTE_R · PTE_W · PTE_X · PTE_U` | `kernel/riscv.h`  | PTE 의 플래그 비트                                           |
| `PTE2PA(pte)`                           | `kernel/riscv.h`  | PTE 에서 페이지 시작 물리 주소를 얻는다                               |
| `PX(level, va)`                         | `kernel/riscv.h`  | 가상 주소에서 해당 단계의 9비트를 뽑아, 그 단계 테이블의 **인덱스**(0~511)를 돌려준다 |
| `MAXVA`                                 | `kernel/riscv.h`  | 쓸 수 있는 가상 주소의 상한 (2³⁸)                                 |
| `walk(pt, va, alloc)`                   | `kernel/vm.c`     | va 가 쓸 PTE 칸의 **주소**를 돌려준다                             |
| `printk(...)`                           | `kernel/printk.c` | 커널 쪽 출력 (예전 버전의 `printf`)                              |

> ℹ️ **`PX` 를 조금 더 자세히** 정의는 세 줄이지만 역할이 서로 다름: `PXMASK` 는 `0x1FF`, 즉 하위 9비트만 남기는 **마스크 상수**,  `PXSHIFT(level)` 은 `PGSHIFT + 9 * level` 로, 몇 비트를 밀지 알려 주는 **숫자 일뿐**. 실제로 9비트를 뽑는 것은 둘을 함께 쓰는 `PX(level, va)` 이고, `va` 를 `PXSHIFT` 만큼 오른쪽으로 민 다음 `PXMASK` 로 마스킹함. **미는 것** 은 원하는 9비트를 LSB 로 쉬프트, **마스킹** 은 그때 위쪽에서 딸려 내려온 비트를 잘라 내는 일. `PGSHIFT` 가 12 이므로 각 단계는 이렇게 대응.
> 
> | level | PXSHIFT | 추출하는 비트 | PX 가 돌려주는 인덱스    |
> | ----- | ------- | ------- | ---------------- |
> | 2     | 30      | 38~30   | L2 (루트) 테이블의 인덱스 |
> | 1     | 21      | 29~21   | L1 테이블의 인덱스      |
> | 0     | 12      | 20~12   | L0 테이블의 인덱스      |
> 
> **예시 — `va = 0x40403123`**  39비트를 9 · 9 · 9 · 12 로 끊으면 각 조각이 이렇게 나옵니다.
> 
> ```
>   000000001   000000010   000000011   000100100011
>     L2 = 1      L1 = 2      L0 = 3     오프셋 = 0x123
> ```
> 
> 매크로는 이 끊기를 **밀기(shift) → 마스킹** 두 단계로 합니다.
> 
> | 무엇을 구하나     | ① 시프트 (`>> PXSHIFT`) | ② 마스킹 (`& 0x1FF`) | 결과        |
> | ----------- | -------------------- | ----------------- | --------- |
> | `PX(2, va)` | `va >> 30` = 1       | `1 & 0x1FF`       | **1**     |
> | `PX(1, va)` | `va >> 21` = 514     | `514 & 0x1FF`     | **2**     |
> | `PX(0, va)` | `va >> 12` = 263171  | `263171 & 0x1FF`  | **3**     |
> | 오프셋         | 시프트 하지 않음            | `va & 0xFFF`      | **0x123** |
> 
> 가운데 줄이 **마스킹이 왜 필요한지** 를 보여 줍니다. 21비트를 밀면 L1 조각이 맨 아래로 내려오지만, 그 위에 L2 조각이 그대로 붙어 따라옵니다.
> 
> ```
> va >> 21  =  000000001 000000010
>    0x1FF  =            111111111
> ```
> 
> `& 0x1FF` 는 **아래 9비트만 남기고 나머지는 0 으로 지우는** 일입니다. 그래서 위에 붙어 있던 L2 테이블에 해당하는 비트(`000000001`) 사라지고 `000000010`, 곧 **2** 만 남습니다.
> 
> 맨 아래 12비트는 **페이지 안 오프셋** 으로만 사용됩니다.
> 
> 거꾸로 조립해 보면 확인됩니다 — `(1 << 30) | (2 << 21) | (3 << 12) | 0x123 = 0x40403123`.
> 
> 끝으로 `PX` 가 돌려주는 것은 **번호 하나** 입니다. 그 칸을 읽으려면 `pagetable[PX(level, va)]` 처럼 배열로 인덱싱해야 하고, 바이트로 따지면 `테이블 시작 주소 + PX × 8` 입니다 ( 한 칸이 8바이트이고 칸이 512개이므로 `512 × 8 = 4096` — 테이블 하나가 페이지 크기와 일치함)

## 3.1 vmprint() — 트리 전체를 순회하기

### 3.1.1 목표

페이지 테이블 하나를 받아 **유효한 칸만** 출력하는 커널 함수 `vmprint()` 를 커널에 넣고, 부팅할 때 첫 프로세스(`init`)의 페이지 테이블이 출력되게 합니다. 강의의 「exec 직후」 그림이 실제 숫자로 나타납니다.

**코드는 모두 주어집니다.** 이 실습에서 할 일은 코드를 넣어 돌려 보고, **재귀 세 단계가 어떻게 그 출력 모양을 만들어 내는지** 를 짚어 내는 것입니다. 빈칸 채우기는 3.2 에서 합니다.

### 3.1.2 학습 내용

- 페이지 테이블 하나가 PTE 512칸짜리 배열이라는 것
- `PTE_V` 로 빈 칸을 거르는 방법, 그리고 `level` 을 하나씩 낮추며 세 단계를 내려가는 재귀 구조
- **재귀의 깊이가 곧 출력의 들여쓰기** 라는 것 — 화면에 출력된 ` ..` 개수를 보면 지금 몇 단계인지 알 수 있다
- `PTE2PA` 의 결과가 다음 단계 테이블의 **시작 주소** 라는 것
- 매핑이 없는 가지는 아예 만들어지지 않는다는 것 — 희소 트리

### 3.1.3 단계별 구현

#### Step 1 — 재귀 출력 함수를 만든다  `(kernel/vm.c)`

파일 맨 아래에 두 함수를 추가합니다. 안쪽 함수가 한 단계를 순회하고, 필요하면 한 단계 더 내려갑니다. 바깥 함수는 루트 주소를 출력한 뒤 재귀를 시작합니다.

`level` 은 **강의의 `PX(level, va)` 와 같은 번호** 를 씁니다. 루트가 2, 그 아래가 1, 맨 아래가 0 입니다. `walk` 의 `for (level = 2; level > 0; level--)` 와 같은 방향입니다.

```
// kernel/vm.c  — add at the bottom of the file

// Print the valid PTEs of one page-table page,
// then descend into lower-level tables.
// level: 2 = root (L2), 1 = L1, 0 = L0  — same numbering as PX(level, va)
static void
vmprint_level(pagetable_t pagetable, int level)
{
  // 테이블 한 장에는 PTE 가 512칸 들어 있다. 0번부터 511번까지 빠짐없이 순회한다.
  for (int i = 0; i < 512; i++) {

    // pagetable 은 uint64 * 이므로 배열처럼 인덱싱하면 i 번째 칸의 값이 나온다.
    // (walk 과 달리 칸의 주소가 아니라 칸에 들어 있는 값 자체를 읽는다)
    pte_t pte = pagetable[i];

    // V 비트가 꺼져 있으면 아무것도 매핑되지 않은 빈 칸이다 — 출력하지 않고 건너뛴다.
    // 512칸 중 대부분이 여기서 걸러진다. 그래서 출력은 몇 줄 되지 않는다.
    if ((pte & PTE_V) == 0)
      continue;

    // ① 깊이 표시 : L2 는 " .." 한 번, L1 은 두 번, L0 는 세 번 출력한다.
    //    level 이 2면 d 가 2 하나뿐이라 1회, level 이 0이면 0·1·2 로 3회 돈다.
    for (int d = level; d <= 2; d++)
      printk(" ..");

    // ② 칸 번호 · PTE 의 값 · 그 PTE 가 가리키는 물리 주소를 한 줄로 출력한다.
    printk("%d: pte %p pa %p\n", i, (void *)pte, (void *)PTE2PA(pte));

    // ③ L2 와 L1 의 칸은 다음 단계 테이블을 가리킨다. level 을 하나 낮춰 내려간다.
    //    L0(level 0) 은 마지막 단계라 더 내려가지 않는다.
    if (level > 0)
      vmprint_level((pagetable_t)PTE2PA(pte), level - 1);
  }
}

void
vmprint(pagetable_t pagetable)
{
  printk("page table %p\n", (void *)pagetable);
  vmprint_level(pagetable, 2);        // 루트는 L2 부터 시작
}
```

> ℹ️ **어디까지 내려가나** 이 커널에서 L2 와 L1 의 유효한 칸은 **언제나 다음 단계 테이블** 을 가리킵니다. 그래서 판단이 단순합니다 — `level` 이 0 보다 크면 한 단계 더 내려가고, L0 에 닿으면 멈춥니다. L0 의 칸이 가리키는 곳은 테이블이 아니라 **데이터 페이지** 라서 더 내려가면 안 됩니다.

> ℹ️ **`PTE2PA` 한 번이면 됩니다** 결과가 곧 다음 테이블의 0번 칸 주소입니다. 커널이 물리 메모리를 같은 주소로 직접 매핑해 두었으므로 `(pagetable_t)` 로 형변환해 그대로 배열처럼 씁니다 — `walk` 가 하던 일과 똑같습니다.

**첫 인자 `pagetable` 은 어디를 가리키나**  — 새로 만들어진 프로세스의 **L2 루트 테이블 시작 주소** 입니다.

```
  kalloc()            4KB 페이지 한 장을 떼어 준다
     |                이 한 장이 곧 L2 루트 테이블 (PTE 512칸)
     v
  uvmcreate()  -->  proc_pagetable()  -->  p->pagetable
                                                |
                          exec 이 새 이미지를 올린 뒤 이 값을 새 루트로 교체
                                                |
                                                v
                              vmprint(p->pagetable)          <- 23 라인
                                                |
                              vmprint_level(pagetable, 2)    <- 24 라인
                                       ^               ^
                              L2 루트의 시작 주소    "여기는 L2" 라는 표시
```

`kalloc` 이 떼어 준 물리 페이지 한 장의 시작 주소이고, 그 페이지 안에 PTE 512칸이 들어 있습니다. 같은 값이 `MAKE_SATP(p->pagetable)` 로 `satp` 레지스터에도 실리므로, **하드웨어 MMU 가 주소 변환을 시작하는 테이블과 같은 물리 페이지** 입니다.

**번호를 붙인 코드**  — 아래 절차 설명에서 이 줄 번호를 가리킵니다. (주석을 뺀 요약본입니다)

```
01  static void
02  vmprint_level(pagetable_t pagetable, int level)
03  {
04    for (int i = 0; i < 512; i++) {
05      pte_t pte = pagetable[i];
06
07      if ((pte & PTE_V) == 0)
08        continue;
09
10      for (int d = level; d <= 2; d++)
11        printk(" ..");
12
13      printk("%d: pte %p pa %p\n", i, (void *)pte, (void *)PTE2PA(pte));
14
15      if (level > 0)
16        vmprint_level((pagetable_t)PTE2PA(pte), level - 1);
17    }
18  }
19
20  void
21  vmprint(pagetable_t pagetable)
22  {
23    printk("page table %p\n", (void *)pagetable);
24    vmprint_level(pagetable, 2);
25  }
```

**세 단계를 차례로 순회한다**  — 매 단계가 하는 일은 같습니다. 512칸을 순회하고, 유효한 칸에서 한 단계 내려갑니다.

```
[단계 1]  vmprint_level 의 첫 번째 호출 — 24 라인이 호출한다
          인자 : pagetable = L2 루트의 시작 주소,  level = 2
          04 라인의 for 문이 L2 의 PTE 512칸을 순회한다

     L2
   +-------+
   | [0]   |  V=1  -> (10·11 라인) " .." 를 1회  -> (13 라인) "0: pte ... pa ..."
   |       |         -> (16 라인) L1 로 내려간다
   | [1]   |  V=0  -> (07·08 라인) 건너뛴다
   |  ...  |  V=0  -> 건너뛴다
   | [255] |  V=1  -> 같은 순서로 출력하고 L1 로 내려간다
   |  ...  |  V=0  -> 건너뛴다
   | [511] |  V=0  -> 건너뛴다
   +-------+

   화면 출력 :   ..0: pte 0x... pa 0x...
```

```
[단계 2]  두 번째 호출 — 단계 1 의 16 라인이 호출한다 (그 호출의 level 2 > 0 이므로)
          인자 : pagetable = L1 의 시작 주소,  level = 2 - 1 = 1
          04 라인의 for 문이 이번에는 L1 의 PTE 512칸을 순회한다

     L1     <- 05 라인의 pagetable 이 이제 이 테이블을 가리킨다
   +-------+
   | [0]   |  V=1  -> (10·11 라인) " .." 를 2회  -> (13 라인) "0: pte ... pa ..."
   |       |         -> (16 라인) L0 로 내려간다
   | [1]   |  V=0  -> 건너뛴다
   |  ...  |  V=0  -> 건너뛴다
   | [511] |  V=0  -> 건너뛴다
   +-------+

   화면 출력 :   .. ..0: pte 0x... pa 0x...
```

```
[단계 3]  세 번째 호출 — 단계 2 의 16 라인이 호출한다 (그 호출의 level 1 > 0 이므로)
          인자 : pagetable = L0 의 시작 주소,  level = 1 - 1 = 0
          04 라인의 for 문이 L0 의 PTE 512칸을 순회한다. 여기서는 더 내려가지 않는다

     L0
   +-------+
   | [0]   |  V=1  -> (10·11 라인) " .." 를 3회  -> (13 라인) "0: pte ... pa ..."
   |       |         -> (15 라인) level 0 이라 더 내려가지 않는다
   | [1]   |  V=1  -> 같은 순서로 출력하고 멈춘다
   | [2]   |  V=1  -> 같은 순서로 출력하고 멈춘다
   | [3]   |  V=1  -> 같은 순서로 출력하고 멈춘다
   |  ...  |  V=0  -> 건너뛴다
   | [511] |  V=0  -> 건너뛴다
   +-------+

   화면 출력 :   .. .. ..0: pte 0x... pa 0x...   (칸 [1] [2] [3] 까지 네 줄)
```

> ℹ️ **출력 한 줄은 `printk` 두 번으로 완성됩니다** 07 라인을 통과하면 **10 · 11 라인이 먼저** 들여쓰기 `" .."` 를 출력하고, **그다음 13 라인이** `"번호: pte … pa …"` 와 줄바꿈을 출력합니다. 들여쓰기 횟수는 `3 - level` 입니다 — level 2 는 1회, level 1 은 2회, level 0 은 3회. 그래서 화면에서 ` ..` 의 개수를 세어 보면 그 줄이 몇 단계에서 출력된 것인지 알 수 있습니다.

> ℹ️ **재귀 호출은 512번이 아닙니다** 16 라인은 for 문 안에 있지만, 08 라인의 `continue` 를 통과한 칸만 거기까지 갑니다. L2 에서 유효한 칸이 둘이면 재귀도 두 번입니다. 재귀가 시작되면 그 가지가 전부 끝날 때까지 바깥 for 문은 같은 `i` 에 멈춰 있습니다.

> ℹ️ **15 라인의 조건은 「지금 호출」이 아니라 「다음 호출」을 결정합니다** `if (level > 0)` 은 그 조건을 평가하는 호출이 **한 단계 아래를 부를지** 정합니다. 단계 1(level 2) 과 단계 2(level 1) 에서는 참이라 각각 다음 호출이 일어나고, 단계 3(level 0) 에서는 거짓이라 **네 번째 호출이 없습니다.** 단계 3 자체는 단계 2 가 불러 준 것입니다 — level 0 이어서 호출이 안 되는 것이 아니라, level 0 인 호출 **안에서** 더 내려가지 않는 것입니다.

L0 의 512칸이 끝나면 **L1 의 다음 칸**으로, L1 이 끝나면 **L2 의 다음 칸**으로 돌아갑니다 — 17 · 18 라인에서 for 문이 다음 `i` 로 넘어가는 것이 곧 그 복귀입니다. 그래서 L2 의 `[255]` 칸에서 같은 세 단계가 한 번 더 일어나고, 그쪽이 trampoline 가지입니다.

> ℹ️ **`walk` 과 무엇이 다른가** `walk` 은 가상 주소를 받으므로 `PX(level, va)` 로 **몇 번 칸인지 계산해서 그 한 칸만** 봅니다. `vmprint_level` 은 가상 주소가 없고 트리 전체를 출력하는 것이 목적이라 **0번부터 511번까지 전부** 순회합니다. 한 단계 내려갈 때 `PTE2PA` 로 다음 테이블의 시작 주소를 얻는다는 점은 둘이 똑같습니다.

읽는 요령은 **` ..` 의 개수가 곧 재귀의 깊이** 라는 것입니다. 한 줄 앞의 ` ..` 이 두 개면 그 줄은 `vmprint_level(…, 1)` 이 출력한 것이고, 그 칸 번호는 L1 테이블의 인덱스입니다.

#### Step 2 — 다른 파일에서 부를 수 있게 선언한다  `(kernel/defs.h)`

### 3.1.4 출력 읽는 법

` ..` 하나가 한 단계입니다. 하나면 L2, 둘이면 L1, 셋이면 L0 입니다.

| 출력 줄                                | 무엇인가                                             |
| ----------------------------------- | ------------------------------------------------ |
| ` ..0` 아래 전부                        | 사용자 메모리 가지 — 프로그램 코드 · 데이터 · 스택 (낮은 주소)          |
| ` ..255 →  .. ..511 →  .. .. ..511` | 주소 공간 맨 꼭대기 = 트램펄린 (`TRAMPOLINE = 0x3FFFFFF000`) |
| ` .. .. ..510`                      | 트램펄린 바로 아래 = 트랩프레임                               |

` ..0` 과 ` ..255` 는 **루트 한 장만 공유하고** 그 아래로는 완전히 별개의 가지입니다. 강의 「exec 직후」 그림의 두 가지가 바로 이 두 덩어리입니다.

### 3.1.5 확인 질문

**(1)**&nbsp;&nbsp; **L2 테이블 512칸 중 출력에 나온 칸이 왜 `0` 과 `255` 둘뿐인지** 따라가 봅시다. 먼저 L2 의 한 칸이 얼마만큼의 주소를 담당하는지 세어 보면 답이 보입니다.

L2 의 칸 하나 아래에는 L1 이 512칸, 그 하나마다 L0 이 512칸, 그 하나마다 4KB 페이지가 달립니다.

```
512 × 512 × 4096 = 2^30 = 1GB
```

즉 L2 의 `[i]` 번 칸은 가상 주소 **`i` GB 부터 `(i+1)` GB 까지** 를 담당합니다. 주소 공간 전체가 `MAXVA` = 2³⁸ = 256GB 이고, 그것을 1GB 씩 512칸으로 나눈 것이 L2 입니다. 그러면 `init` 의 주소들이 어느 칸에 들어가는지 세 줄로 정리됩니다.

| L2 칸     | 담당 구간         | 그 안에 무엇이 있나                                                            |
| -------- | ------------- | ---------------------------------------------------------------------- |
| `[0]`    | 0 ~ 1GB       | 프로그램의 코드 · 데이터 · 스택. 0번지부터 놓이고 크기는 몇 KB 뿐이라 전부 여기                      |
| `[255]`  | 255GB ~ 256GB | 트램펄린 `0x3FFFFFF000` (= 256GB − 4KB). `0x3FFFFFF000 ÷ 0x40000000 = 255` |
| 나머지 510칸 | 1GB ~ 255GB   | 아무것도 매핑되지 않음 → 그 아래 테이블이 아예 만들어지지 않음                                   |

프로그램이 쓰는 곳은 **주소 공간의 맨 아래 1GB** 와 **맨 위 1GB** 뿐이고, 가운데 254GB 는 비어 있습니다. 이것이 「희소 트리」라는 말의 뜻입니다.

이어서 생각해 보세요 — 만약 어떤 프로그램이 메모리를 1GB 넘게 쓴다면 L2 에 어떤 칸이 더 켜질까요?

**(2)**&nbsp;&nbsp; `vmprint_level` 안의 for 문은 한 번 호출될 때 512번 돕니다. 그런데 출력은 열 줄 남짓입니다. 나머지 500여 번은 어디로 갔습니까?

**(3)**&nbsp;&nbsp; 만약 `if (level > 0)` 이 없다면 무슨 일이 벌어질까요? L0 의 칸이 가리키는 곳은 테이블이 아니라 **데이터 페이지** 라는 점을 생각해 답해 보세요.

**(4)**&nbsp;&nbsp; 깊이 표시의 `for (int d = level; d <= 2; d++)` 를 `d < 2` 로 바꾸면 출력이 어떻게 달라집니까? 왜 그런지 설명해 보세요.

## 3.2 va2pa() — 주소 하나를 따라 내려가기

### 3.2.1 목표

사용자 프로그램이 넘긴 가상 주소 하나를 커널이 `walk` 로 따라가 **물리 주소로 바꿔 돌려주는** 시스템 호출 `va2pa()` 를 만듭니다. 내려가는 도중 각 단계의 칸 번호도 함께 출력합니다.

강의 「전체 추적」 슬라이드에서 손으로 했던 계산을, 이번에는 커널이 대신 해 줍니다.

### 3.2.2 학습 내용

- `PX(level, va)` 로 세 칸 번호와 오프셋을 뽑는 방법
- `walk(pt, va, 0)` — **alloc = 0** 이면 찾기만 하고 테이블을 만들지 않는다는 것
- `PTE2PA` 는 페이지 **시작** 주소만 준다 — 오프셋은 따로 더해야 한다
- 매핑이 없는 주소, 매핑은 있지만 사용자용이 아닌 주소를 구분하는 방법

**한 갈래만 따라 내려간다**  — 3.1 은 512칸을 모두 순회했지만, 여기서는 `PX` 가 고른 **한 칸씩** 만 봅니다. 각 단계에서 다음 테이블의 **시작 주소** 를 얻는 것이 핵심입니다.

```
[1]  L2  — 시작 주소는 satp 가 준다
       +-------+
       | [0]   |   <- 이 칸의 위치가 곧 L2 의 시작 주소
       |  ...  |
       | [ i ] |   i = PX(2, va)   ->  이 칸의 PTE2PA 가 L1 의 시작 주소
       |  ...  |
       | [511] |
       +-------+

[2]  L1  — 시작 주소는 L2 의 [ i ] 칸이 준다
       +-------+
       | [0]   |   <- L1 의 시작 주소
       |  ...  |
       | [ j ] |   j = PX(1, va)   ->  이 칸의 PTE2PA 가 L0 의 시작 주소
       |  ...  |
       | [511] |
       +-------+

[3]  L0  — 시작 주소는 L1 의 [ j ] 칸이 준다
       +-------+
       | [0]   |   <- L0 의 시작 주소
       |  ...  |
       | [ k ] |   k = PX(0, va)   ->  이 칸의 PTE2PA 가 페이지의 시작 주소
       |  ...  |
       | [511] |
       +-------+

     페이지의 시작 주소  +  va 의 아래 12비트  =  최종 물리 주소
```

`[1]` ~ `[3]` 은 `walk` 이 대신 해 주고, 맨 아래 한 줄이 TODO ② 가 할 일입니다.

> ℹ️ **이번에는 copyout 이 필요 없습니다** 사용자가 준 주소를 **읽거나 쓰지 않고**, 그 숫자를 페이지 테이블로 **번역만** 합니다. 결과는 숫자 하나라 반환값(`a0`)으로 충분합니다.

### 3.2.3 단계별 구현

#### Step 1 — 번호를 배정한다  `(kernel/syscall.h)`

이 브랜치는 `riscv` 에서 갈라져 나왔으므로 여기 있는 시스템 호출은 `SYS_sync 22` 가 마지막입니다. 그래서 `va2pa` 는 **23** 번을 씁니다.

```
#define SYS_sync   22
#define SYS_va2pa  23        // 추가
```

> ℹ️ **Lab 2 에서도 23 을 썼는데요?** Lab 2 의 `freepages` 는 `lab2-syscall` 브랜치에만 있고, 이번 브랜치는 독립적 코드입니다. 번호는 항상 **지금 브랜치의 코드 기준** 으로 셉니다.

#### Step 2 — 선언하고 표에 등록한다  `(kernel/syscall.c)`

```
// 파일 위쪽, 다른 extern 들 옆에

// syscalls[] 배열 안에
static uint64 (*syscalls[])(void) = {
  ...
  [SYS_sync]    = sys_sync,
  [SYS_va2pa]   = sys_va2pa,        // 추가
};
```

#### Step 3 — 커널 쪽 함수를 구현한다  `(kernel/sysproc.c)`

인자로 받은 가상 주소를 **현재 프로세스의** 페이지 테이블에서 찾습니다. 검사가 세 줄인 이유는 아래 상자에 있습니다.

```
// kernel/sysproc.c  — 파일 맨 아래에 추가

uint64
sys_va2pa(void)
{
  uint64 va;
  pte_t *pte;
  struct proc *p = myproc();

  argaddr(0, &va);                    // 0번째 인자를 주소로 읽는다
  if (va >= MAXVA)
    return 0;                         // 이대로 walk 에 주면 커널이 panic 한다

  // TODO ①  va 의 칸 번호 셋과 페이지 안 오프셋을 한 줄로 출력한다.
  //          printk("va %p : L2=%d L1=%d L0=%d off=0x%x\n", ...);
  //          - 칸 번호 셋 : PX(2, va) · PX(1, va) · PX(0, va)
  //          - 오프셋     : va 의 아래 12비트  (va & 0xFFF)
  //          PX는 각 단계에서 사용할 9비트 인덱스(0~511)를 추출한다.
  //          %d 인자는 int로, %x 인자는 unsigned int로 변환해 출력한다.

  pte = walk(p->pagetable, va, 0);    // alloc = 0 : 찾기만 하고 만들지 않는다
  // 중간 테이블이 없으면 pte == 0, 마지막 칸이 무효이면 PTE_V == 0이다.
  if (pte == 0 || (*pte & PTE_V) == 0)
    return 0;                         // 매핑이 없다
  if ((*pte & PTE_U) == 0)
    return 0;                         // 매핑은 있지만 사용자용이 아니다

  // TODO ②  va 의 물리 주소를 돌려준다. 두 조각을 더하면 된다.
  //          - 페이지 시작 주소 : PTE2PA(*pte)
  //          - 페이지 안 오프셋 : va 의 아래 12비트
  //          PTE2PA는 플래그를 제외한 물리 페이지 번호를 시작 주소로 복원한다.
  //          페이지 안의 위치는 변환 전후 같으므로 원래 오프셋을 더해 반환한다.
}
```

> ⚠️ **왜 `MAXVA` 를 먼저 거르나** `walk` 의 첫 줄은 `if (va >= MAXVA) panic("walk");` 입니다. 사용자가 아무 숫자나 넘길 수 있는데 그대로 `walk` 에 주면, 죽는 것은 사용자 프로그램이 아니라 **커널** 입니다. 사용자에게서 온 값은 커널 함수에 넣기 전에 먼저 걸러야 합니다.

> ℹ️ **검사 세 줄이 각각 무엇을 거르나** `pte == 0` — 중간 테이블조차 없다. `PTE_V` 가 0 — 칸은 있지만 비어 있다. `PTE_U` 가 0 — 매핑은 있지만 사용자 것이 아니다(트램펄린 · 트랩프레임처럼 커널만 쓰는 페이지).

> ℹ️ **`argaddr` 는 채워 두었습니다** Lab 2 의 `sysinfo` 에서 본 그 함수입니다. 0번째 인자를 주소로 읽어 `va` 에 넣습니다.

> ℹ️ **`walk` 는 따로 선언할 필요가 없습니다** `kernel/defs.h` 에 이미 있고 `sysproc.c` 가 그 헤더를 포함합니다.

#### Step 4 — 사용자 쪽에 노출한다  `(user/user.h, user/usys.pl)`

```
// user/user.h  — system calls 묶음 안에
uint64 va2pa(uint64);

// user/usys.pl  — entry 목록 끝에
entry("va2pa");
```

#### Step 5 — 테스트 프로그램을 만든다  `(user/va2patest.c)`

프로그램의 세 영역 — **코드 · 데이터 · 스택** — 에서 주소를 하나씩 골라 넣어 봅니다. 강의에서 본 사용자 주소 공간 그림의 세 칸이 실제로 어디에 놓이는지 확인하는 셈입니다.

```
#include "kernel/types.h"
#include "kernel/stat.h"
#include "user/user.h"

int global = 42;                      // 데이터 영역에 놓인다

void
show(char *name, void *va)
{
  printf("%s  va %p -> pa %p\n", name, va, (void *)va2pa((uint64)va));
}

int
main(void)
{
  int local = 7;                      // 스택에 놓인다

  show("text ", (void *)main);        // 함수의 기계어가 놓인 곳 = 코드 영역
  show("data ", &global);
  show("stack", &local);

  exit(0);
}
```

```

커널의 `printk` 한 줄과 사용자의 `printf` 한 줄이 번갈아 나옵니다. 아래는 **예시** 입니다. 주소 값은 여러분 환경에서 다르지만, 뒤에 나오는 **패턴** 은 같아야 합니다.

```
va 0x0000000000000068 : L2=0 L1=0 L0=0 off=0x68
text   va 0x0000000000000068 -> pa 0x0000000087f40068
va 0x0000000000001010 : L2=0 L1=0 L0=1 off=0x10
data   va 0x0000000000001010 -> pa 0x0000000087f3e010
va 0x0000000000003fbc : L2=0 L1=0 L0=3 off=0xfbc
stack  va 0x0000000000003fbc -> pa 0x0000000087f3cfbc
```

| 줄                   | 확인할 패턴                                             |
| ------------------- | -------------------------------------------------- |
| text · data · stack | **L0 칸 번호가 서로 다르다** — 세 영역이 같은 L0 테이블의 다른 칸에 들어 있다 |
| 세 줄 모두              | pa 의 **아래 12비트가 va 와 똑같다**                         |

### 3.2.4 직접 계산해 확인하기

출력된 va 하나를 골라 **직접 계산해** 보세요. 위 예시의 `stack` 줄이라면 이렇게 됩니다.

```
va = 0x0000000000003fbc

L2  = (va >> 30) & 0x1FF = 0
L1  = (va >> 21) & 0x1FF = 0
L0  = (va >> 12) & 0x1FF = 3
off =  va        & 0xFFF = 0xfbc
```

계산한 값이 커널이 출력한 `L2=0 L1=0 L0=3 off=0xfbc` 와 같다면, **하드웨어 MMU 가 하는 계산을 그대로 따라 한 것** 입니다. 이어서 pa 의 마지막 세 자리(`…fbc`)가 오프셋과 같은지도 확인해 보세요 — 오프셋은 변환되지 않고 그대로 붙기 때문입니다.

> ⚠️ **3.1 의 출력과 맞춰 보지는 마세요** `vmprint` 는 **pid 1(`init`)** 의 페이지 테이블만 출력하는데, `va2patest` 는 다른 프로세스라 물리 페이지가 전혀 다릅니다. 같은 프로세스의 트리와 맞춰 보고 싶다면 아래 확장 과제를 하세요.

> ℹ️ **확장 과제 — 같은 프로세스의 트리와 맞춰 보기** `sys_va2pa` 안에서 처음 한 번만 `vmprint(p->pagetable)` 를 호출하게 해 보세요(`static` 변수 하나면 됩니다). 그러면 `va2patest` **자신의** 트리가 출력되므로, 방금 변환한 pa 가 그 트리의 어느 줄에서 나온 것인지 직접 찾아볼 수 있습니다.

### 3.2.5 확인 질문

## 종합 — 두 실습 비교

|           | vmprint()                            | va2pa()                              |
| --------- | ------------------------------------ | ------------------------------------ |
| 방향        | 트리 **전체** 를 위에서 순회한다                 | 주소 **하나** 를 따라 내려간다                  |
| 시스템 호출    | 아니다 — 커널 안에서만 호출한다                   | 그렇다 — SYS_va2pa 23                   |
| 대상 테이블    | pid 1 의 테이블                          | 부른 프로세스 **자신** 의 테이블                 |
| 핵심 도구     | `PTE_V` · `level` 판정 · `PTE2PA` · 재귀 | `PX` · `walk(…, 0)` · `PTE2PA` + 오프셋 |
| 강의의 어느 그림 | 「exec 직후」 두 가지 트리                    | 「walk 한 줄씩」 · 「전체 추적」                |

두 실습은 같은 동작의 **두 방향** 입니다. vmprint 는 재귀로 **모든 가지** 를 내려가고, va2pa 는 `walk` 로 **한 가지만** 내려갑니다. 칸을 고르는 방식만 다를 뿐 — vmprint 는 0부터 511까지 전부, walk 는 `PX` 가 고른 한 칸 — 한 단계 내려갈 때마다 `PTE2PA` 로 다음 테이블의 0번 칸을 얻는다는 점은 같습니다.
